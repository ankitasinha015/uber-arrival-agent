# Synthetic trace set — failure findings (first error-analysis pass)

Generated by `python -m evals.gen_synthetic --live` → 40 traces (28 extraction, 12
ranking) in `extraction_traces.jsonl` / `ranking_traces.jsonl`. Dimensions were chosen
to target anticipated failures, not arbitrary variation. This is the first pass of
error analysis; categories below are what the traces actually revealed.

## Surface A — booking-email extraction (28 traces, deterministic parser)

Accuracy clustered cleanly by email FORMAT — each cluster is a distinct failure mode
tied to a brittle regex anchor in `_extract_via_parse`:

| Format | Acc | Failure category | Broken anchor |
|---|---|---|---|
| canonical | 100% | — (baseline) | — |
| arrow-unicode (`→`) | 75% | **airport-miss** — non-ASCII arrow | `->` literal |
| accommodation-label | 75% | **hotel-miss** — alt label | `hotel:\n` |
| inline-hotel | 75% | **hotel-miss** — hotel in prose | `hotel:\n` |
| 24h-time | 75% | **arrival-miss** — no AM/PM | `arrives HH:MM AM/PM` |
| numeric-date | 75% | **arrival-miss** — `MM/DD` date | `Mon DD` |
| terse-codes | 25% | **multi-field collapse** — SMS codes | several at once |

These are the deterministic parser's known brittleness. The product path is the LLM
extractor (`use_llm=True`); the actionable eval is to **re-run the same 28 emails with
the LLM path and measure how much of each format it recovers** — that quantifies the
value of the LLM over the parser, per format.

## Surface B — dinner ranking (12 traces: 3 taste profiles × 4 cities, live geo)

### 🔴 cuisine-misclassification (real bug)
`_match_cuisine` aliases are too greedy. The "American" bucket includes `bbq`, `grill`,
`barbecue`, so non-American restaurants get tagged American and suggested as the
traveler's match:

- `mexican-dominant@Los Angeles` → **Moonhan Korean BBQ** tagged `[American]`, badge
  "matches what you order", why "you order american a lot".
- `burger-common@Los Angeles` → same restaurant, same misclassification.

Korean BBQ ≠ American. Impact: a confident, badged suggestion that doesn't match the
traveler's actual taste. **Fix:** tighten aliases (drop `bbq`/`grill` from American or
rank them last; add a Korean/Asian bucket), and/or require a stronger match before the
"matches what you order" badge.

### 🟢 graceful degradation (confirmed working)
When the traveler's #1 cuisine isn't open near the hotel, the ranker correctly falls to
the highest-*available* cuisine and the copy stays honest — "closest to your taste
that's open near your hotel — you order X **a lot**", never a false "most":

- `mexican-dominant@Berlin` → no Mexican nearby → Pizza, honest copy.
- `ramen-niche@San Francisco` → no ramen at the Wharf → Burger, honest copy.

This is the honesty fix from the arrival work; the traces confirm it holds across all
four cities. Only genuine #1-available cases say "most" (Mexican@NY, Ramen@Berlin/LA,
Burger@NY/Berlin/SF).

## Next steps (per the eval audit)
1. Fix `cuisine-misclassification` (tighten `_CUISINE_ALIASES`); re-run ranking traces.
2. Run extraction traces through the LLM path; compare per-format recovery.
3. Turn these categories into **binary, single-failure judges** (`write-judge-prompt`):
   e.g. *"Is the badged top pick genuinely the traveler's cuisine? PASS/FAIL"*.
4. Hand-label a held-out slice and validate the judges (TPR/TNR, `validate-evaluator`).

## Update — after the eval-package fixes

- **cuisine-misclassification: FIXED.** Tightened `_CUISINE_ALIASES` (dropped weak
  bbq/grill/steak from "American"). Re-ran the 12 ranking traces: LA now resolves to
  CoCo Ichibanya [Ramen] (a Japanese ramen chain), not "Korean BBQ [American]". The
  `cuisine_match` evaluator validates this at TPR/TNR 100% and gates it in CI.
- **honest_copy: 0 failures** across the regenerated traces (no false "most" claims).
- **New secondary finding:** the "matches what you order" badge can land on a very
  low-ranked cuisine (Ramen #6 for a burger-lover) when nothing better is open nearby,
  with a stretchy "you order X a lot". Next: extend `honest_copy` to flag "a lot" on a
  bottom-half cuisine, and soften the copy/badge for those cases.
